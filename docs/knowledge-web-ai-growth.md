# Addendum: AI-grown patterns

Extends docs/knowledge-web-spec.md. Build this after spec steps 1–7 are working.

## The idea

The lace around each bubble should reflect *understanding*, not just memory. FSRS can tell when a fact is remembered. It can't tell whether you can explain it or connect it to other ideas. The on-device AI adds that second signal, and also chooses how each bubble's pattern looks.

The AI never invents drawing code. It picks from the fixed motif library (spec section 6) and from a small set of parameters, so patterns stay clean and consistent.

## 1. Two kinds of layers

Split the 5 lace layers into two groups:

| Layers | Earned by | Meaning |
|---|---|---|
| 1–3 | FSRS stability (3, 7, 21 days) | You **remember** it |
| 4–5 | AI-graded understanding | You **understand** it |

- Layers 1–3 work exactly as in spec section 3.
- Layer 4 needs layer 3, plus one passing **Explain** answer for that bubble.
- Layer 5 needs layer 4, plus one passing **Connect** answer linking it to a neighbor.
- Layers never go away once earned, same as the spec.

## 2. Understanding prompts

Add two card types, generated by the AI from the bubble's existing cards and summary (not stored as regular FSRS cards):

- **Explain:** "Explain chunking in your own words, with an example."
- **Connect:** "How does chunking relate to working memory's capacity limit?"

When a bubble reaches layer 3 (or 4), study mode occasionally offers one of these instead of a regular card (at most 1 in 5 cards). The user types an answer. The on-device model grades it against the bubble's cards and summary and returns JSON:

```json
{ "verdict": "solid" | "partial" | "missing", "feedback": "one or two sentences" }
```

- Use grammar-constrained JSON, like card generation (src/ai/prompt.ts).
- Show the feedback either way. Only "solid" earns the layer.
- Store each attempt in a new table: understanding_attempts(id, node_id, kind, related_node_id, answer, verdict, feedback, created_at).
- A "solid" Connect answer also adds paired beads to that strand right away (in addition to the spec's rule).

Small models misjudge sometimes, so let the user override a verdict ("I think I got this") and log the override.

## 3. Patterns that mean something about the topic

Every bubble's pattern should be a visual metaphor for its topic, for any subject, not only the psychology seed data. The spec's motif library only covers memory topics, so instead of picking a finished motif, the AI writes a **pattern recipe**: one drawing instruction per layer, built from a fixed vocabulary of shapes. The app draws it. The AI never writes drawing code.

### Step 1: find the metaphor

When a bubble is created (seed data, Add tab, PDF import), ask the model what the idea *is like*. It picks one or two themes from this list:

| Theme | Fits ideas about | Example topics |
|---|---|---|
| branching | growth, spreading, causes and effects | neurons, decision trees, evolution |
| orbit | things revolving around a core | working memory, atoms, attention |
| layers | building up over time, depth | long-term memory, geology, habits |
| radiance | energy, focus, influence outward | attention, motivation, the sun |
| grouping | clustering, categories, parts of a whole | chunking, taxonomy, sets |
| hub | control, coordination, a center directing parts | central executive, government, a CPU |
| containers | limits, slots, capacity | capacity limit, budgets, context windows |
| waves | rhythm, repetition, sound, oscillation | phonological loop, practice, cycles |
| balance | two sides, tension, trade-offs | Stoic dichotomy of control, supply and demand |
| barrier | protection, boundaries, filtering | API key security, immune system, defenses |
| flow | movement through stages, pipelines | training stages, digestion, agent loops |
| lattice | structure, regular order, networks | crystals, embeddings, social networks |
| spiral | gradual progress, compounding | spaced repetition, learning curves |
| sparks | scattered fragments, creativity, sketching | visuospatial sketchpad, brainstorming |

### Step 2: write the recipe

The model returns grammar-constrained JSON:

```json
{
  "theme": "balance",
  "reason": "The Stoic split between what is and isn't in our control",
  "layers": [
    { "shape": "dots",      "count": 12, "size": "small" },
    { "shape": "half-arcs", "count": 2,  "style": "solid-vs-dashed" },
    { "shape": "ticks",     "count": 12, "length": "alternating" },
    { "shape": "beads",     "count": 6,  "side": "solid-half" },
    { "shape": "ring",      "style": "wavy" }
  ]
}
```

- Shapes come only from a fixed vocabulary implemented in code: dots, ring (plain, wavy, dashed, broken), arcs, half-arcs, ellipses, rays, ticks, branches, forks, chevrons, squares, diamonds, small circles, brackets, beads, crosses, spiral, lattice.
- Each shape has a few allowed settings (count 2–24, size small/medium/large, style, length). Enforce them with the JSON schema enum and range limits.
- Layer 1 is closest to the bubble; layers appear as they're earned (section 1).
- Store the recipe on the node (replace `motif`/`motifParams` with a `pattern` JSON column). Keep the spec's hand-made motifs as built-in recipes, so the seed data still looks like the mockup.
- Show the `reason` when the user long-presses a bubble, so they can see why it looks the way it does. It doubles as a small memory hook.

### Step 3: safety nets

- Validate the recipe. If the call fails or returns something invalid, pick a theme's default recipe by hashing the title.
- Draw every recipe inside the same size limit (about 42 px past the bubble edge) so bubbles never collide.
- Long-press menu: "Regenerate pattern" (asks the AI again) and "Choose theme" (pick from the table).
- Bubbles in the same web should look different from each other: pass the neighbors' themes to the model and ask it to avoid repeating them when another fit is reasonable.
